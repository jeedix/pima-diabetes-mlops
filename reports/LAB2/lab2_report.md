## 1. Схема настроек (pydantic)

Конфигурация описана моделью `Lab2Config` (`src/config.py`), состоящей из трёх вложенных схем:

- **`DataConfig`** — путь к данным (`raw_path`), целевая колонка (`Outcome`), `test_size`, `seed`, размер чанка (`chunk_size`). Валидатор `@field_validator("raw_path")` проверяет, что файл существует.
- **`PipelineConfig`** — стратегия импутации (`mean` / `median` / `most_frequent`), тип scaler (`standard` / `minmax` / `none`), модель (`logreg` / `sgd`), гиперпараметры (`model_params`).
- **`TrainingConfig`** — режим (`full` / `chunks`), число бутстрэп-итераций (`n_bootstrap`), имя MLflow-эксперимента.

**Ограничения pydantic:**
- `test_size ∈ [0.1, 0.4]` — задано как `Field(0.2, ge=0.1, le=0.4)`
- `chunk_size ∈ [16, 1024]` — `Field(128, ge=16, le=1024)`
- `model ∈ {logreg, sgd}` — `Literal["logreg", "sgd"]`
- `raw_path` — файл должен существовать

При невалидной конфигурации программа останавливается с `ValidationError` и объяснением (см. `reports/LAB2/config_negative_test.log`, три случая).

## 2. Состав конвейера

**Режим full:**
1. `SimpleImputer(strategy=median)` — заполняет `NaN` медианой (нули в Glucose, BloodPressure, SkinThickness, Insulin, BMI преобразованы в NaN на этапе чтения)
2. `StandardScaler` — нормирует признаки (mean=0, std=1)
3. `LogisticRegression(max_iter=1000, class_weight=balanced)` — бинарная классификация с компенсацией дисбаланса классов

**Режим chunks:**
1. `SimpleImputer(strategy=median)`
2. `StandardScaler`
3. `SGDClassifier(loss=log_loss, max_iter=1, tol=0.001)` — обучение через `partial_fit` на чанках по 128 записей

**Обоснование выбора моделей:**
- `LogisticRegression` — интерпретируемая линейная модель; `class_weight=balanced` компенсирует дисбаланс классов (65% / 35%).
- `SGDClassifier` — единственная модель в sklearn, поддерживающая `partial_fit` для инкрементального обучения чанками.

**Различие между режимами:** `class_weight=balanced` используется только в `full`, потому что `partial_fit` не поддерживает его (sklearn выдаёт `ValueError`). Это объясняет небольшое расхождение recall между режимами.

## 3. Способ подбора параметров

Гиперпараметры зафиксированы в конфигах из карточки варианта:
- `max_iter=1000` для LogReg — достаточно для сходимости на Pima (768 записей)
- `class_weight=balanced` — компенсация дисбаланса
- `loss=log_loss`, `tol=0.001` для SGD

**Подбор гиперпараметров не выполнялся.** Контрольная часть использована **один раз** для финальной оценки — это соответствует требованию спецификации (стр. 75: «контрольная часть использована один раз»).

## 4. Сравнение режимов

### 4.1. Метрики с 95% доверительными интервалами

| Метрика | Full (95% CI) | Chunks (95% CI) | Δ |
| Accuracy | 0.734 (0.662–0.805) | 0.714 (0.636–0.786) | 0.020 |
| Precision | 0.603 (0.483–0.721) | 0.578 (0.459–0.700) | 0.025 |
| Recall | 0.704 (0.574–0.829) | 0.685 (0.543–0.804) | 0.019 |
| F1 | 0.650 (0.545–0.748) | 0.627 (0.509–0.723) | 0.022 |
| ROC-AUC | 0.813 (0.741–0.873) | 0.795 (0.723–0.858) | 0.018 |

**Все метрики получены через бутстрэп** (1000 итераций, `seed=42`). CI = 2.5% и 97.5% перцентили распределения бутстрэп-оценок.

### 4.2. Наивный ориентир

Мажоритарный класс (0 — нет диабета) даёт:
- **Accuracy = 0.651**
- **F1 = 0.000** (для класса 1 ничего не предсказано)

Модель превосходит наивный ориентир по accuracy на **0.083** и по F1 на **0.650**.

### 4.3. Время и память

| Режим | Время обучения, с | Пик памяти, МБ |
| full | 0.019195899999886024 | 0.31842 |
| chunks | 0.00968349999993734 | 0.259024 |

Пик памяти в режиме чанков **не превышает** пик полного режима — ограничение по памяти соблюдено.

### 4.4. Объяснение расхождения метрик

Разница между режимами по всем метрикам **≤ 0.025**. Причины:
1. Разные модели: LogReg vs SGDClassifier.
2. `class_weight=balanced` доступен только в `full`.
3. SGD обучается 1 эпоху (`max_iter=1` при `partial_fit`), что может дать чуть меньшую точность.

**Доверительные интервалы всех метрик пересекаются** — статистически значимого различия между режимами нет.
